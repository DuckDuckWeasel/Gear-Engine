# Application startup (composition root)

A minimal **UGS + Cloud Code + LiveOps** host (no gameplay) lives in [`MetaApplicationBootstrap`](../../Assets/GearEngine/Scripts/App/Bootstrap/MetaApplicationBootstrap.cs) (`Game.App.Bootstrap`), used by [`Assets/GearEngine/Scenes/Meta.unity`](../../Assets/GearEngine/Scenes/Meta.unity). It is built on **`Scaffold.LayeredScope`** ([`ApplicationBootstrap`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.layeredscope/Runtime/ApplicationBootstrap.cs), package `com.scaffold.layeredscope`). See [Meta bootstrap](../Meta/Bootstrap.md) and [LiveOps bootstrap](../LiveOps/Bootstrap.md) for layer order, build, `.ccmr`, and Play Mode notes.

For new scenes prefer **`MetaApplicationBootstrap`**-style wiring with explicit [`IScopeLayer`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.layeredscope/Runtime/Contracts/IScopeLayer.cs) types, or your own [`TwoScopeApplicationHost`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.scope/Runtime/Host/TwoScopeApplicationHost.cs) subclass if you need the older Scaffold host.

Wire your full game by **subclassing** [`TwoScopeApplicationHost`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.scope/Runtime/Host/TwoScopeApplicationHost.cs) in **your** assembly: implement `InstallBaseScope` (e.g. Addressables), `PrepareMainScopeAsync` (preload), and `InstallMainScope` (infra modules, navigation, UGS, scene flow, LiveOps, etc.). See [`Startup-Two-Scope-Preload.md`](../../Plans/Startup-Two-Scope-Preload.md).

Optional loading UI: subscribe to [`ApplicationStartupProgress.Changed`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.scope/Runtime/Host/ApplicationStartupProgress.cs) on the host’s [`StartupProgress`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.scope/Runtime/Host/TwoScopeApplicationHost.cs) property, or override [`GetStartupProgressListener`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.scope/Runtime/Host/TwoScopeApplicationHost.cs) to supply a custom [`IApplicationStartupProgress`](https://github.com/MgCohen/Scaffold/blob/main/Assets/Packages/com.scaffold.scope/Runtime/Contracts/IApplicationStartupProgress.cs).

## Data-driven publisher SOs (editor iteration path)

For fast iteration without adding a new typed publisher class per catalog, use [`AddressableScriptableObjectPublisherSO`](../../Assets/GearEngine/Scripts/App/Bootstrap/Publishers/DataDriven/AddressableScriptableObjectPublisherSO.cs): assign an **Addressable** `ScriptableObject` on the asset, then **Rebuild** in the inspector (or **Tools → Bootstrap → Rebake All Publisher SOs**). That bakes a closed-generic [`AddressableScriptableObjectPublisherRegistrar<T>`](../../Assets/GearEngine/Scripts/App/Bootstrap/Publishers/DataDriven/AddressableScriptableObjectPublisherRegistrar.cs) into a `[SerializeReference]` field so **runtime registration uses no reflection**—the same pattern as hand-written publishers, but data-authored.

- **Where to wire**: assign rebaked [`AddressableScriptableObjectPublisherSO`](../../Assets/GearEngine/Scripts/App/Bootstrap/Publishers/DataDriven/AddressableScriptableObjectPublisherSO.cs) assets to **Addressable catalog publishers** on [`GearAppFlowRoot`](../../Assets/GearEngine/Scripts/App/Bootstrap/Layers/FoundationLayer.cs) subclasses ([`CampaignApplicationBootstrap`](../../Assets/GearEngine/Scripts/App/Bootstrap/CampaignApplicationBootstrap.cs), [`MetaApplicationBootstrap`](../../Assets/GearEngine/Scripts/App/Bootstrap/MetaApplicationBootstrap.cs)). [`FoundationLayer`](../../Assets/GearEngine/Scripts/App/Bootstrap/Layers/FoundationLayer.cs) registers `IAddressablesAssetClient`, `IAddressablesGateway`, navigation, events, and the publishers. Default repo assets live under [`Assets/GearEngine/Data/Bootstrap/`](../../Assets/GearEngine/Data/Bootstrap/) (`CatalogPublisher_*`); open the project once or run **Tools → Bootstrap → Rebake All Publisher SOs** so the bake is populated. Catalog entry addresses are centralized in [`AddressableCatalogAddresses`](../../Assets/GearEngine/Scripts/App/Bootstrap/AddressableCatalogAddresses.cs) for reference.
- **Custom load order**: replace or subclass [`FoundationLayer`](../../Assets/GearEngine/Scripts/App/Bootstrap/Layers/FoundationLayer.cs) only if you need a different sequence (e.g. extra `IAsyncScopeLayer` / `PrepareAsync` work before catalog `IAsyncInitializable` publishers run). [`GearAppFlowRoot`](../../Assets/GearEngine/Scripts/App/Bootstrap/Layers/FoundationLayer.cs) always yields foundation first; game layers come from `GetGameLayers()`.
- **Bake lifecycle**: importing or changing the `.asset` triggers an automatic rebake when the addressable key or target type drifts; use **Rebuild** if the bake looks stale.
- **IL2CPP / stripping**: types are marked with `[Preserve]` as a best-effort hint. **Before shipping** the SO-driven path to device builds, verify a **stripping-on** player build and add a type-witness or `link.xml` entry if closed generics are stripped (follow-up; not required for editor-only iteration).
